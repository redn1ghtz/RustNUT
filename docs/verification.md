# Проверки RustNUT 0.1.0-alpha

| Требование | Покрытие |
| --- | --- |
| NUT TCP, обнаружение и показания | Loopback-сервер, выбор ИБП, экранирование, повреждённые и устаревшие ответы. Синтетические профили APC, Eaton и CyberPower проверяют разные наборы переменных, включая частоту на выходе, активную мощность и неполную телеметрию |
| TLS и авторизация | Локальные STARTTLS и прямой TLS через Schannel, проверка имени и цепочки, отказ при недоверии, отсутствие отката к TCP, принятие и отказ в авторизации |
| Фоновый режим и переподключение | Поллинг со скрытым окном, отключение и повторное подключение, остановка фонового worker |
| Трей и окно | Запуск EXE на Windows 10 22H2 x64 через WOW64, проверка значка Explorer, повторного запуска, растягивания таблицы, входа в полноэкранный режим по F11 и выхода по Esc |
| Настройки и автозапуск | Запуск с другим рабочим каталогом, сохранение рядом с EXE и повторная загрузка, сброс после подтверждения, DPAPI с проверкой повреждённого блока, тест записи и удаления значения в изолированном разделе реестра, запуск с `--background` |
| Интерфейс | Светлая и тёмная темы, сетка одинаковых шкал, выровненные кнопки настроек, подпись активной мощности, производитель и серийный номер. Проверены размеры окна, сглаживание углов при масштабах 100%, 150% и 200%, прокрутка и десять размеров иконки EXE от 16 до 256 px |
| Напряжение | Проверены десятичная точка и запятая, появление и исчезновение `battery.voltage`, отображение измерения за пределом шкалы. На проверенном POWERCOM вход и выход составляли по 232 В. `LIST VAR` не содержит поля напряжения батареи, а прямой `GET VAR powercom battery.voltage` вернул `ERR VAR-NOT-SUPPORTED` |
| Уведомления | Проверены английские и русские заголовки и тексты всех событий. Сквозная проверка вызывает переход на батарею и потерю связи с включёнными уведомлениями. Фактический показ всплывающего окна Explorer отдельно не подтверждён |
| Действия питания | Проверяются пороги, задержки, FSD, свежесть данных, отмена и срабатывание по первому показанию от батареи. Сквозной тест на обычном TCP проверяет отказ и согласие в диалоге сохранения, состояние зависимых полей и сохранение опций «При работе от батареи» и «Выключать без подтверждения». Реальные сон, гибернация и выключение не запускаются |
| Диапазоны | Автоматическая проверка границ, номинальной частоты и отключения ограничений. Сквозной тест проверяет заполненные значения по умолчанию, переключатель и отметку о выходе за пределы |
| Сборка и пакет | Rust fmt, Clippy, тесты Windows и проверка PE x86. Windows читает версию продукта `0.1.0-alpha`, версию файла `0.1.0.0` и признак предварительной сборки. Проверена ссылка разработчика в интерфейсе и свойствах EXE |

## Отчёт антивируса

SHA-256 из отчёта VirusTotal для 0.2.0 совпал с локальным EXE (`c545457f317ce89be52bef42e326c549808f805f3a0f7a9011471e5b35cf567a`). Microsoft Defender при локальной проверке не обнаружил угроз в 0.2.0, 0.3.0, 0.3.1, 0.3.2 и оптимизированной 0.1.0-alpha. Сборки без подписи Authenticode. Результат локальной проверки не отменяет детекты других поставщиков. [Как VirusTotal обрабатывает споры о детектах](https://docs.virustotal.com/docs/false-positive)

## Расход ресурсов

Windows 10 22H2 x64, сборки x86 Release через WOW64. Сравнивались две сборки 0.1.0-alpha до и после оптимизации. В обеих сборках для замера использовалось отдельное имя экземпляра. Локальный NUT-стенд возвращал стабильные показания каждые 2 секунды. Каждый режим измерялся 30 секунд с выборкой памяти раз в 0,5 секунды. Рабочий набор включает разделяемые страницы. Счётчик CPU показал 0,000 % одного логического ядра в обоих прогонах во всех трёх режимах при доступном разрешении измерения.

| Режим | Рабочий набор до → после | Частная выделенная память до → после |
| --- | ---: | ---: |
| Запуск в трее, окно ещё не открывали | 9,74 → 9,35 МиБ | 2,05 → 1,93 МиБ |
| Открытое окно | 12,65 → 12,60 МиБ | 2,97 → 2,93 МиБ |
| Свёрнуто в трей после открытия | 12,66 → 12,60 МиБ | 2,97 → 2,93 МиБ |

При отдельном контрольном замере по 15 секунд на режим рабочий набор составил 9,34 МиБ при запуске в трее, 12,57 МиБ при открытом окне и 12,62 МиБ после сворачивания в трей. На каждом интервале счётчик CPU показал 0,000 % одного логического ядра при доступном разрешении. Сквозная проверка также покрывает смену значения автономности, отсутствие данных и сохранение позиции прокрутки при обновлении таблицы.

Для повторения в интерактивном сеансе Windows с Explorer нужны Python 3.10+ и собранный EXE. Стенд использует отдельный файл настроек, loopback и выключенную политику завершения работы.

```powershell
python scripts/smoke.py dist/RustNUT-windows-x86/rustnut.exe --samples 30
```

## Оставшиеся проверки

- Повторить сквозной тест на 32-битной Windows 10 и Windows 11 x64. Доступен был один хост Windows 10 x64.
- На тестовой машине с Explorer проверить визуальный показ уведомлений, перезапуск Explorer и настоящий вход в сеанс с включённым автозапуском.
- На отдельной VM подтвердить фактическое штатное выключение, сон и гибернацию, состояние приложений с несохранёнными данными и отмену предупреждения. Проверить потерю TLS-соединения и восстановление после сна во время отсчёта.
- Проверить многочасовую работу с физическим ИБП и реальным `upsd`. Текущие автоматические тесты используют управляемые loopback-стенды.
- GitHub Actions прописан для веток, PR и релизных тегов. Для подтверждения его работы нужен запуск в опубликованном репозитории.
